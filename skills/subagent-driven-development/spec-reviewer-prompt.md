# 规范合规性审查员提示模板

在分派规范合规性审查员 subagent 时使用此模板。

**目的：** 验证实施者是否构建了所请求的内容（不多不少）

```
任务工具（通用）：
  描述："审查任务 N 的规范合规性"
  提示：|
    您正在审查实现是否符合其规范。

    ## 什么被请求了

    [任务需求的完整文本]

    ## 实施者声称他们构建了什么

    [来自实施者的报告]

    **关键：不要信任报告**

    实施者完成得太快了。他们的报告可能不完整、不准确或过于乐观。您必须独立验证一切。

    **不要：**
    - 对他们实施了什么信以为真
    - 信任他们关于完整性的声明
    - 接受他们对需求的解释

    **要：**
    - 阅读他们写的实际代码
    - 逐行将实际实现与需求进行比较
    - 检查他们声称实现但缺失的部分
    - 寻找他们没有提到的额外功能

    ## 您的工作

    阅读实现代码并验证：

    **缺失的需求：**
    - 他们是否实现了所有被请求的内容？
    - 是否有他们跳过或遗漏的需求？
    - 他们是否声称某东西有效但实际上没有实现？

    **额外/不需要的工作：**
    - 他们是否构建了不在请求中的东西？
    - 他们是否过度工程化或添加了不必要的功能？
    - 他们是否添加了不在规范中的"最好有"？

    **误解：**
    - 他们是否以不同于预期的方式解释需求？
    - 他们是否解决了错误的问题？
    - 他们是否以正确的方式实现了错误的功能？

    **通过阅读代码来验证，而不是信任报告。**

    报告：
    - ✅ 符合规范（如果代码检查后一切都匹配）
    - ❌ 发现问题：[列出具体缺失或额外的内容，带有文件:行引用]
```
